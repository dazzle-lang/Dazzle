# 21. Changelog

Revisions of the unreleased 0.1. Every change to the **language** — syntax, semantics, or a
§18 decision — gets a row here, whether or not the compiler has caught up with it yet.
Compiler-only work belongs in `docs/tasks/` while open and `docs/log/` once done, not here.

| Revision | Date | Change |
|---|---|---|
| r82 | 2026-10-29 | **Writing plain data kills nothing** (§6.7, D-0091). r81 said writing a place kills every tie under it, inline storage included, which made every setter of plain data (`ball = Vec2{…}`) need a `kills` clause although nothing moved. Now moving or dropping a place still kills everything under it, but **writing one kills only what the old value owned** (a `String`'s text, a `List`'s array) **and, for a tagged union or an optional, references into its payload**. A reference into a plain value survives the write, as it survives `p.x += 1`, and a function that only writes plain data needs no clause. A call's clause reaches as a write does: `kills w` can free what `w` owns or change its payloads, but leaves a reference to a plain field of `w` valid. |
| r81 | 2026-10-27 | **Ties: a reference used after a call moved its memory is an error, and the compiler places memory** (§6.7, §14.6, D-0091; revises §1.1, §5.2, §6.4, §14, §14.1, §2.7, §20; supersedes D-0010 and, in part, D-0047). A type names the storage it owns with `in @name` on a field (`m_data: own ^mut T in @items`), and **every function declares in a `kills` clause which ties it ends** — `fn push(&mut self, v: T) kills self@items`; no clause kills nothing, and the clause must say exactly what the body kills: a kill it leaves out, a path the body never kills, and a path wider than what dies are all errors, each with the clause the body needs, which `dz fix` writes and the editor offers. A trait method without a body, an `extern fn` and a function type have nothing to hold a clause to, so theirs is a promise: the most an implementation may kill. Every reference carries a tie, so using one after a call killed it is an error: `let n = counts.get_or_insert(k, 0)`, then `counts.insert(o, 1)`, then `n += 1` no longer compiles. A function returning a reference says where it points with `in` (`-> ^T in self@items`); a tie path reaches elements with `[*]` — of an array, a slice, or a type with an `Index<usize>` or `Iterable` implementation, and only `Index` gives a path anything to go on into; `kills` is a keyword; a function type names its parameters where its clause needs them, and parenthesises a clause of more than one path (`fn(w: &mut World) kills (w.a@items, w.b@items)`). Aliasing stays legal: `&mut xs[i]` beside `&xs[j]` is fine, and only a call that can move the memory makes a later use an error. **Ordinary code names no allocator**: no allocator parameters and no `Allocators::Temp` in user code; each value goes in the most efficient place the compiler can prove safe — its scope's region, wherever the caller wants a returned value, else the heap. Decided; not yet implemented (T-0107): until it is, containers still take allocators and nothing is checked. |
| r80 | 2026-10-24 | **A recipe can build a library with its own CMake** (§15.1, D-0090). `cmake = "vendor/SDL"` in a `[cpp.libs.<name>]` recipe replaces its `sources`, `include_dirs` and `defines`: `dz` configures, builds and installs the library with CMake and its own C and C++ compilers, as a static library. `import` reads the headers it installed, and the pkg-config file it installed gives the link line. `options = { SDL_TEST_LIBRARY = false }` are its `-D` settings. Debug builds CMake's `Debug`, release and shipping its `Release`. CMake is needed only by a project with such a recipe. Before, a library with a configure step had to have that step's output generated by hand and vendored. |
| r79 | 2026-10-24 | **A C field whose struct has no name is imported** (§15.2). `struct { … } playback;` inside a C struct, as miniaudio's `ma_device_config` has, was left out of the import, with no way to set what it holds; it is now an ordinary field, so `config.playback.format = ma::ma_format::ma_format_f32` works as it does in C. Its struct is named after the owner and the field, `ma_device_config_playback`, should a program need to write the type. |
| r78 | 2026-10-23 | **Arguments convert through `ImplicitAs<T>`** (§7.2, §7.6, §14.4, D-0087, D-0088, D-0089). A type implementing `std`'s new `ImplicitAs<T>` is converted to a `T`, by its `convert(&self) -> T`, where it is passed as an argument to a parameter of type `T`; `std` implements it for `String` and `Path` to `cstr`, so `rl::DrawText(format!("score {}", n), …)` and `rl::LoadTexture(path)` work without `.as_cstr()`. Only arguments convert, never a `let`, a field or a `return`; the argument is borrowed, not moved; one conversion at most; and none to choose a C++ overload or infer a generic. **The orphan rule counts a trait's type arguments**, as Rust's does: `impl ImplicitAs<Vec2> for rl::Vector2` and `impl Mul<Vec2> for f32` belong with `Vec2`. **An imported header's types belong to the module carrying its recipe**, which may implement any trait for them — `impl Mul for rl::Matrix`. |
| r77 | 2026-10-23 | **Projections name their depth range** (§14.4, D-0086). `Mat4::perspective` and `Mat4::orthographic` take a `DepthRange` as their last argument, with no default: `.MinusOneToOne` for OpenGL and raylib, `.ZeroToOne` for Vulkan, Direct3D, Metal and SDL3's GPU API. Before, both always produced OpenGL's -1..1, which draws wrongly, with no error, on any of the others. Existing calls add `.MinusOneToOne` to keep what they did. |
| r76 | 2026-10-23 | **A struct's layout is C++'s** (§7.3, §5.5, D-0085). Fields are in memory in declaration order, a base's first, with the padding and alignment the target's C++ compiler gives them; nothing is reordered to save space. A Dazzle struct is therefore layout-identical to a C or C++ struct with the same fields in the same order, and `T::size` and `T::align` are that compiler's answer. Programs already behaved this way; the spec now promises it. To make a struct smaller, order its fields largest alignment first. |
| r75 | 2026-10-23 | **Associated-type projection** (§8.5). A generic body may name an associated type through a bound — `T::Item` for a `T: Iterate`, `C::Iter::Item` for a `C: Iterable`, `T::Output` for a `T: Add` — in a signature, a local, a field or another implementation's choice (`type Item = (usize, I::Item)`). Inside the body it is one type, checked once against what the trait says of it: `Iterate`'s `Item` has no bounds, so it is moved and never copied. At each instance it is what the implementation chose. A name no bound declares is `DZ0560`; one that two bounds declare, each with its own answer, is `DZ0561`. So **`for` over a generic `T: Iterate` or `C: Iterable` now works**, where it was refused (`DZ0801`). |
| r74 | 2026-10-22 | **No `alloc` or `free` builtins** (§5.2, §14, D-0084). Memory comes only from an `Allocator`: write `Allocators::Global` (or a container's `^mut Allocator`) and call its `alloc` and `free`, which are told the size and alignment. `alloc(…)` and `free(…)` are now unknown names (`DZ0301`). Underneath, `Allocators::Global` calls C's `malloc` and `free` through the standard library's own import of `stdlib.h`, which a program cannot name. **A system header can be imported** (§15.1): `import = ["stdlib.h"]` in a recipe brings in its declarations and those of the system headers it includes, where before it brought in nothing; a system header reached through a library's own header is still left out. §5.2's list of what is `unsafe` now names `move_out` and `memmove`, which already were. |
| r73 | 2026-10-22 | **`SlotMap<T>` and `Key<T>`** (§14.4, §14.5, D-0083). A map that hands out a `Key<T>` for each value it takes: `insert`, `get` and `get_mut` (a `^T`, `null` once the value is removed), `remove` (a `T?`), `contains`, `retain`, `clear`, `for k, &v in m`, and `values()` as a slice. A key is eight copyable bytes — `Eq`, `Hash`, `Format`, rebuilt from `index()` and `version()` — that a struct can keep in a field where it cannot keep a reference; a key to a removed value reads as absent, even after its slot is reused. `Key<Enemy>` is not `Key<Bullet>`. **There is no reference to a reference** (§5.2): `&r` and `&mut r` on a reference `r`, and `&mut list[i]` through `IndexMut`, refer to what `r` refers to. They had been typed as a reference to a reference, which no generated C++ could express. |
| r72 | 2026-10-22 | **A generic base** (§7.3). A struct may inherit an instance of a generic struct — `struct Button : Panel<i32>` — getting its fields and methods with the base's parameters read as its arguments, and constructing it with `: Panel(…)`; a generic derived type may pass its own parameter on, `struct Slider<T> : Panel<T>`. A reference converts to the base at those arguments only. Before, a base with type arguments was an error (`DZ0541`), and `&Slider<T>` did not convert even to a non-generic base. |
| r71 | 2026-10-22 | **Constructors are chosen by their arguments** (§7.2, §7.3). A call to a type with several constructors, and a base initialiser `: Base(…)`, reaches the one that takes that many arguments — defaults counted — and whose parameters they fit, exact types breaking a tie; one still left with more than one candidate is an error (`DZ0538`). Before, every call took the first constructor declared, so the others could not be reached. **A defaulted `#location` has the call's column**, and its `function` is the caller's Dazzle name (`Counter::bump`), where it had been column 0 and C++'s unqualified name (§12.7). |
| r70 | 2026-10-22 | **No `impl` for a pointer or reference type** (§7.6). `impl Hash for ^Node`, `impl<T> Show for ^T` and the like are errors (`DZ0539`): a method call reaches through a pointer to what it points at (§5.2), so such an implementation could never be called directly, and through a bound it reached C++ as a call on the pointee. To give a pointer behaviour of its own — keying a map by identity, say — wrap it in a struct and implement the trait for that. Formatting a pointer is unaffected; it is done by the formatting macros (r69). |
| r69 | 2026-10-22 | **Formatting a pointer** (§12.9, D-0080, D-0082). A pointer argument of a formatting macro is written as what it points at, as a reference is — one level down, with a spec applying to what it points at — and a null one as `null`, where it used to be an error. **`{:p}`** writes a pointer's address, in hex after `0x` on every platform, padded by a width as a number is; it suits a pointer only, and takes no zero fill. In `error(…)` a pointer is written only by `{:p}`, and `{}` on one is now an error. A type parameter bounded by `Format` is still not satisfied by a pointer. |
| r68 | 2026-10-21 | **An operator reads through a reference** (§5.2, D-0081): an operand of a comparison, arithmetic or bitwise operator that is a `&T` of a number, `bool`, `char`, `str` or enum is its value, whether or not a type is wanted of the result — `x > 2` and `let y = x * 2` on a `&i32`, which were errors. **Keeping a view of a temporary is an error, `DZ0407`** (§6.5): a temporary is dropped at the end of its statement, so a `str`, `cstr`, slice, reference or pointer taken from one through a method, field, index or slice may be passed to a call in that statement but not kept by `let`, assignment or `return` — `let c = String::from(name).as_cstr()`, which compiled and read freed memory. |
| r67 | 2026-10-21 | **The collections pass** (§5.3, §14.2, §14.3, §14.4, D-0081). **`List`** gains `first`, `last`, `first_mut`, `last_mut` (a `^T`, `null` when empty), `remove_range(from, to)`, `retain(keep)`, `append(&mut other)`, `reverse` and `shrink_to_fit`; **`Search<T>`** gives a list of `Eq` elements `contains` and `index_of`, and **`Extend<T>`** a list of `Copy` ones `extend`, `insert_slice` and `fill`; a list of `Eq` elements is `Eq` and of `Hash` ones `Hash`. **`HashMap`** gains `get_or_insert(key, default)` (a `&mut V`), `retain(keep)`, `keys()`, `values()` and `values_mut()`, and a `HashMap<String, V>` is looked up by `str` with `get_str`, `get_mut_str`, `contains_str` and `remove_str` (**`StrKeys`**). **`HashSet<T>`** is new: `insert`, `contains`, `remove`, `retain`, `for &v in set`, and `contains_str`/`remove_str` on a `HashSet<String>`. **`String`** gains `insert`, `insert_str` and `remove`; **`Text`** gains `rfind`, `strip_prefix`, `strip_suffix`, `split_once`, `split_whitespace`, `eq_ignore_ascii_case` and `repeat`; **`Join`** writes `names.join(", ")` for a `[]str`, `List<str>` or `List<String>`. **`memmove(dst, src, n)`** joins the placement primitives as an `unsafe` overlapping copy, and `List` moves byte-relocatable elements with it rather than one at a time. A runtime `str` reaches C as `String::from(s)` and then `as_cstr()` — the `String` is the owning C string 18.39 promised. §14.4 no longer says plain integer arithmetic makes no promise on overflow: it wraps (18.63). |
| r66 | 2026-10-21 | **Widths in format specs** (§12.9). `{:N}` writes a value in at least `N` characters, padded with spaces, and `{:0N}` a number padded with zeros after its sign; the width comes first and combines with the rest, `{:8x}`, `{:08X}`, `{:10.3}`. A number is right-aligned and anything else left-aligned; the width counts characters, never cuts, and pads a type's own `Format` as a whole. It holds in `error(…)` too. A width of `0`, a zero fill with no width, and a zero fill on anything but a number are errors at the placeholder. `Formatter` gains `width()` and `fill()`. Choosing the alignment (`{:<8}`, `{:>8}`) is left out. |
| r65 | 2026-10-21 | **A macro's kind decides its spelling** (§12.5, §12.7, §12.8, §12.9, 18.9, 18.80). What reads like a call takes `!`, one bracketed group: an `expr` macro is `max!(a, b)`, in any expression, a statement included; a `stmt` macro is `log!("warn", "hp is {}", hp)`, as a whole statement, and its pattern now matches its brackets as an `expr` macro's does; the formatting macros are `println!(…)`, `format!(…)`, `panic!(…)` and the rest. A `decl` macro keeps `#`, running to the end of the line: `#machine ButtonState(…) { … }`. A dependency's is `dep::max!(…)` or `#dep::machine …`. The other intrinsics stay `#file`, `#line`, `#location`, `#expr_text(e)`. Each macro has one spelling, and writing the other is an error that says which to use. |
| r64 | 2026-10-20 | **Formatting is a set of macros** (§12.5, §12.8, §12.9, §9.8, 18.80). `print(…)`, `println(…)`, `eprint(…)`, `eprintln(…)` and `panic(…)` are now written `#print(…)`, `#println(…)`, `#eprint(…)`, `#eprintln(…)` and `#panic(…)`, and **`String::format(…)` is `#format(…)`**, still taking `allocator = …` by name — the compiler's own macros, beside the intrinsics, whose names are now reserved too. The format string is checked as before; what changes is what may be formatted: **any type that implements `Format`**, where `println` used to take only the built-in kinds — so `#println("{}", v)` prints a `Vec2` with its own `Format`, and a `String` directly. The arguments are evaluated as a call's are. A pointer is no longer printable as an address; write what it points at. `#panic`'s message is cut at a few hundred bytes, since it is built without allocating. `error(…)` is unchanged. In `std`, `Formatter` is built with `Formatter::string(&mut text)`, `Formatter::stdout()` or `Formatter::stderr()`, and gains `flush` and `set_spec`. A string literal written `"'a'"` keeps its quotes, which it used to lose. |
| r63 | 2026-10-20 | **Macros, settled for M10** (§12, 18.9, 18.74–18.79). **One invocation spelling, `#name`, everywhere** — `name!(…)` is gone: in declaration and statement position an invocation runs to the end of the line, in expression position it is one bracketed group, and a dependency's macro is `#dep::name`. The intrinsics are the compiler's own macros, and `error` joins their reserved names. **Patterns read like parameters and types**: `$name: ident`, `$t: type`, `$xs: [,]Field`, `$xs: []State`, `$d: expr?`, `$( … )?` for an optional group; kinds are `ident`, `literal`, `type`, `expr`, `stmt`, `block`, `code`, `decl` or a `syntax` rule, and a macro is `-> decl`, `-> stmt` or `-> expr` (`type` reserved). Matching never backtracks. **`expand` is shaped by `#for v in $xs[,] { $v.name }`, `#if $x { … } #else { … }` and `#error($x, "…")`**, replacing `$xs[,] { $.name }` and `$x? { … }`; an `#if` on anything but a capture is still the build-flag `#if`. **Hygiene hides an expansion's locals but not its declarations**, and other names in `expand` resolve where the macro is declared. **Macros expand on syntax, before resolution**, so `T::fields` of a type parameter is deferred and a per-field macro takes the declaration instead (§12.11, §13.4). `pub macro` exports a macro; an expansion may invoke macros but not declare one. A diagnostic in captured code points at that code, one in generated code at the invocation with an "in expansion of" note. **Unions may declare methods** (§7.5, 18.78), which `#machine`'s `step` needed. |
| r62 | 2026-10-20 | **Arguments passed by name, and library formatting** (§7.2, §12.9, §14.4, 18.72, 18.73). The parameters after a variadic one are passed by name, `name = value`, after the other arguments and in any order; nothing else is. So "variadic last" (18.56) becomes "at most one variadic". **The global `format` is gone**: `String::format("…", args, allocator = …)` returns a `String` — no more four shared 256-byte buffers, so a long or a fifth message is no longer cut or overwritten. `Format` is implemented for the numbers, `bool`, `char`, `str`, `cstr` and `String`, and a type of your own can implement it; `Formatter` appends text and reports the placeholder's spec. A format string is checked at compile time in `String::format` as in `println`; a formatting function of one's own waits for macros (M10). `println` and friends are unchanged. |
