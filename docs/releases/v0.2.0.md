## What's new in 0.2

Dazzle 0.2 carries the language at spec revision r143; 0.1 was r117. Each change below is
a row in [the changelog](https://dazzle-lang.github.io/spec/21-changelog/), with its reasons
and its decision.

### Changes a 0.1 program may notice

- **Values move by default** (r135). A by-value use of anything that is not plain data
  moves it, with nothing written; a copy is `a.clone()`, and `move(x)` and `copy` are gone.
  `dz fix` writes the `.clone()` where a program used a value after moving it.
- **`{}` writes a float in its shortest digits that read back** (r130): `0.1 + 0.2` prints
  `0.30000000000000004`, where it printed `0.3`.
- **`loop` is a keyword** (r131); a program using it as a name renames it.
- **A field and a method may not share a name** (r122).
- **A prefix operator binds tighter than `as`** (r124): `-x as u8` is `(-x) as u8`.
- **A `for` range's bounds are evaluated once** (r128).
- **A `Box<Derived>` converts to a `Box<Base>` only when `Base` has a `virtual` method**
  (r133), and only a plain struct of its own module may implement `Allocator` (r132).

### The language

- **Homes** (r119, r120): every value that owns memory has a home, a region or the heap,
  and a `sends` clause says where a function hands what it is given, so the compiler places
  memory where it lives long enough, across calls and through traits.
- **Generic trait methods** (r139), `fn write<T: Format>(&mut self, value: T)`, called on a
  value or through a bound.
- **`indexed()` is a value** (r138), and every sequence is cut with `[a..b]`, text by
  bytes or by characters (r129).
- **A union payload field may have a default** (r136), a constructor a `kills` clause
  (r140), and `#[inline]` inlines every call in an optimised build (r137).
- **The standard library** has `BinaryHeap` and `Reverse` (r125), `Deque` (r126) and
  `BitSet` (r127). `String`, `List` and `Box` are smaller: 32, 32 and 8 bytes (r132, r133).

### C and C++

- **Dear ImGui is called as C++ writes it**: default arguments left out, overloads chosen by
  their arguments, array parameters by reference (r118). A dependency names a namespace
  bare, `imgui = { cpp = "imgui", namespaces = ["ImGui"] }`, so code writes `ImGui::Begin`
  (r141). `printf`-style functions, `ImGui::Text`, `SetTooltip`, `SDL_Log`, take one text,
  passed after a `"%s"` (r143).
- **Dependencies fetched with git** (r142): a Dazzle module or a C or C++ library names a
  repository and a `version` or a `rev`; `dazzle.lock`, checked in, pins the commit. The
  SDL3 example's ImGui is fetched this way, and the example no longer needs raylib.

### Faster builds

`dz` keeps what it compiled: each generated file has its own object, the runtime and the
standard library are compiled once per machine with a precompiled header, imported headers
are kept between builds, a build with nothing changed skips analysis, and an edit checks only
the modules it can affect.

| | 0.1 | 0.2 | the same program in C++ |
|---|---:|---:|---:|
| A small program, debug, from clean | 0.76–0.89 s | 0.29–0.35 s | 0.28–0.47 s |
| A small program, release, from clean, against C++ | 3.3–4.7× | 1.1–1.7× | |
| 100 modules, debug, from clean | 60 s | 8.2 s | 5.2 s |
| 100 modules, after a one-line edit | 15 s | 0.88 s | 1.10 s (`make`) |

### Run time

Seven whole programs run against their C++ halves, built by the same compiler. At 0.2,
Dazzle takes 0.70× to 1.06× as long, against 0.77× to 1.17× at 0.1 for the three programs
measured then. New since 0.1: a JSON reader and writer, a ray tracer, a battle on an ECS
library (also against Rust), and generic code instantiated six times over. Every run is now
recorded, so a regression shows as a ratio that moved
([benchmarks](https://dazzle-lang.github.io/project/benchmarks/)).
